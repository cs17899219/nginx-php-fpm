## Changes and compatibility

- Only exact `/index.php` forwards to FPM, with fixed `$document_root/index.php`. Missing entry returns 404.
- Pretty routes internally fall back to `/index.php$is_args$args`; direct `/index.php?r=...` remains supported. No external redirect or application response-format changes.
- Other PHP-like paths (`php`, numbered PHP extensions, `phtml`, `phar`, case-insensitive, including PATH_INFO) return 404. The deny regex precedes static locations.
- Dotfiles are denied before static matching. The broad `.well-known` exception is removed. TLS and domain validation must terminate outside this container.
- Existing file/directory and static-extension precedence is retained. Routes colliding with real directories or static extensions require application-level checks.
- Internal require/include is unaffected. PHP-FPM's `security.limit_extensions = .php` is defense in depth, not a filename allowlist.
- Nginx workers and FPM use `nginx`; the Unix socket is `/var/run/php-fpm.sock`, owned by `nginx:nginx`, mode `0660`.
- The base's existing `cgi.fix_pathinfo=0` remains unchanged. `.user.ini` scanning is NOT disabled: first audit business/monitoring dependencies and writable directories.

## Startup contract

`/start.sh` validates WEBROOT before the inherited script can interpolate it, forces `SKIP_CHOWN=1`, then runs `/start-base.sh`. The inherited script now fails on errors, including failing init hooks. After init/Composer and before Supervisor, `/start.sh --final` installs the controlled site, writes the ordered FPM include config, and runs both config validators. Any failure stops startup.

Supervisor loads `/usr/local/etc/php-fpm-entry.conf`, including the original `www.conf` followed by `/opt/entry-security/entry-security.conf`; existing pool sizing remains configurable. Repeated startup regenerates the security configuration and does not append duplicate `display_errors` entries.

`WEBROOT` defaults to `/var/www/html`; supported overrides are safe absolute subdirectory paths such as `/var/www/html/frontend/web`, resolving inside that tree. Only the `@WEBROOT@` placeholder is replaced, never Nginx variables. `PHP_CATCHALL` is no longer needed. `REAL_IP_HEADER=1` and IP/CIDR `REAL_IP_FROM` remain supported; trust only actual proxies.

This is deliberately a single HTTP site, same-container Unix socket profile. The following require a reviewed migration and are rejected at startup:

- `/var/www/html/conf/nginx/nginx.conf`, `nginx-site.conf`, or `nginx-site-ssl.conf`;
- extra available/enabled sites, including container-managed HTTPS;
- changes to the main Nginx config, fastcgi_params, or main Supervisor config (including `HIDE_NGINX_HEADERS=0`).

The inherited inactive SSL example is removed during build. Application scripts editing default.conf will have those edits replaced by the final template: migrate required timeouts, upload limits, real-IP rules, logs, aliases, and custom error handling into reviewed image configuration first. The stock static cache, 100m upload limit, error page, and error-page image aliases are retained.

Configuration, module includes, Supervisor extensions and root init hooks must be controlled by trusted deployment owners. This is not a sandbox against container root or malicious deployment configuration.

## Code permissions

Disabling recursive chown does NOT repair existing worker ownership/ACLs. Deploy source and entry files read-only or owned by a deployment identity; explicitly grant only required runtime/upload/backend asset directories. Do not recreate removed frontend/callapi assets, recursively chmod/chown code, or assume HTTP entry restrictions prevent file inclusion/command execution vulnerabilities. Writable index.php remains a risk.

## Audit follow-up

- `/usr/bin/pull` is disabled and exits nonzero without modifying files. Deploy a rebuilt application image instead of refreshing a live checkout.
- The default index returns only `OK`, not phpinfo/environment data.
- Composer is pinned to 2.11.2 with a checked SHA-256; the obsolete prestissimo plugin is removed. Startup Composer remains optional via `SKIP_COMPOSER`.
- `PHP_MEM_LIMIT` sets a positive integer MB value. Xdebug is off by default; `ENABLE_XDEBUG=1` uses a single loader. PHP version exposure is disabled through a PHP INI file.
- SSH Git checkout now requires verified host keys supplied in `/root/.ssh/known_hosts`. Do not disable verification to bypass an unknown host.
- Each supervised service has a 60-second graceful shutdown budget. Allow **150 seconds** at container level (`docker stop --time 150`, Compose `stop_grace_period: 150s`, or Kubernetes `terminationGracePeriodSeconds: 150`). Longer application request budgets need corresponding changes; the Docker default timeout is too short.
- GitHub Actions automatic publication is removed. Build, test and push images manually; Git tags do not publish anything.

## Release gate and rollback

Before publishing/deploying, validate the full build and downstream extension image; record digests and config versions. Do not reinstall this security layer in the downstream Dockerfile: inherit up2 and validate FPM with `--fpm-config /usr/local/etc/php-fpm-entry.conf`.

Capture controlled, sanitized `nginx -T` / `php-fpm -tt --fpm-config /usr/local/etc/php-fpm-entry.conf`, actual identities, WEBROOT, includes, socket/ACLs, and rollback commands. Audit old init/Vagrant/remote-dev configs separately. Complete the agreed F01–F09 and S01–S12 acceptance per service: frontend/callcenter first, then backend/callapi/collectionapi, including real login/pages/assets, multipart attachments, text callbacks, encoded JSON/Yii JSON/JSONP, health/error behavior, unauthorized socket access and code ownership. Run the application's existing frontend/legacy JSON tests too.

Use test accounts and side-effect-free fixtures. Canary for the agreed window (suggested >=30 minutes) and a restart, checking error rate, callback success, socket errors and 502/504. These business/remote checks remain outstanding.

Rollback both image digest AND mounted config; restore only recorded ACL/ownership changes, never chmod 777. Recheck routes, health, callbacks and backend assets; remove probes. Warn operations that rolling back can reopen other PHP entry points.
